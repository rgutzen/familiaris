**The name.** The skeleton that holds the shape and is not itself the work. The
register gives no gloss for this one — the name appears in the subject register
and nowhere else — so the reading offered here is this page's own: a skeleton is
what makes a body one thing rather than a pile, and it is the part nobody looks
at until it is wrong.

## The mechanism

Four top-level buckets ordered by **actionability** rather than by topic: a
project with an end, an area held to a standard, a Zettelkasten for thinking, a
resource shelf. The layout is configuration — one master file the tree is built
from and the documentation is generated from, so the drawn tree and the described
tree cannot drift.

Naming is part of the structure, not a style preference: a structural file means
something by its name (`CONTEXT.md` routes, `INDEX.md` discloses, `README.md` is
the human entry), and a content file is named so that it identifies itself read
alone, without the folder around it.

## The design choice, and why

**The generated master file.** A layout documented by hand is a layout that
disagrees with itself within a month; a layout generated from one source means
the answer to "where does this go" is a file, not a paragraph.

**Filing asks when, not what.** Ordering by actionability is the choice that
makes the inbox worth having: a note can be filed before anyone decides what it
is *about*, because the question the layout asks is when it is needed.

## Lineage

[One row](../lineage.md), and its limit is in it: the layout borrows PARA's
ordering — Projects, Areas, Resources, Archives — and then departs from it in
three visible ways. Three of the four buckets are here, a Zettelkasten sits
between Areas and Resources, and no Archives folder exists at the top level.
Named source, **partial correspondence**.

A second row — the Zettelkasten folder — is about `03_ZETTEL` and stops the same
way. Luhmann's method is a way of reading a slip box; the folder keeps the name.

**Where the analogy stops.** A skeleton implies a body that grew it. This one was
chosen, is written in a config file, and can be changed by editing that file —
which is the whole point, and the opposite of a bone.
