# Knowledge index — progressive disclosure, subjects then leaves

`knowledge/INDEX.md` is the entry between `CONTEXT.md` and any knowledge leaf:
every SUBJECT, with its leaves' trigger terms. Each subject's own
`knowledge/<branch>/<subject>/INDEX.md` lists its leaves, one line each, with
their terms. Both are read on demand and injected nowhere. (One flat index until
2026-10-21; see O3d below.) It is a **derived artifact** — edit the leaf,
not the index. The scoring rules that decide which leaves survive are
[[memory-ranking]]; what belongs in this tree at all is `knowledge-vs-skills.md`.

## Content

**Generated by** `familiar knowledge index [--check]`
(`engine/knowledge/knowledge_index.py`), and by stage 7 of
the nightly pass alongside the skill routers. `--check` exits 3 on drift and
writes nothing; `pazras-healthcheck` runs it that way.

| Field | Source on the leaf | Fallback |
|---|---|---|
| What it holds | `summary:` | `title:` → H1 → filename |
| Trigger terms | `triggers:` | `tags:`, capped at 8 |
| A subject's terms (top index) | its leaves' terms, one from each in turn | capped at 12 |
| Branch heading | the branch router's own `LAYER n · …` comment | none |

Nothing in the index is authored by the generator. A generated summary would be
knowledge living in a cache, and the next rebuild would overwrite it.

**Budget: 2,000 tokens, and the budget is the feature.** An index that grows
without bound is the injected block again, just voluntary. Over budget is a
content problem a human fixes by shortening `summary:` lines or splitting a
branch; the generator still writes the file (a stale index is worse than an
oversized one) and returns 1. Measured 2026-09-11: 27 leaves, 4,039 chars,
~1,010 tok.

**Over budget, split (O3d) -- executed 2026-10-21, per SUBJECT.** The rule
said: stay flat until `INDEX_BUDGET_TOKENS = 2000` is exceeded, then split per
branch. It was exceeded at 39 leaves (~2,017 tok), and **every leaf was in
`system/`**, so a branch split would have moved the whole table one directory
down and stayed over. The user chose the split per subject. Measured after it:
the top index 3,140 chars (~785 tok), 14 subject indexes, the largest
(`consolidation`) 1,576 chars. The budget is now **per file**; the warning names
the largest. The cost is a second routing level, which the generator's own
docstring cites evidence against (one level suffices); the top level keeps the
first hop a vocabulary match by carrying each subject's leaf terms. A subject
whose leaves are gone loses its index on the next rebuild.

**The ~12 rule is measured per router, and it warns rather than split** (the
measurement applied 2026-10-13; the verdict below stands). The unit is the
directory whose `CONTEXT.md` lists the rows: `system/CONTEXT.md` triages
thirteen subjects, so `system/` is measured per subject — the largest holds 8 —
and `areas/<A>/` is measured the same way. A warning is a signal, never an
order to split: **sub-levels are derived from the leaves an Area actually
holds**, not invented ahead of them (`areas/A_Science/neuro/…` today would be
the invention). The user's 2026-10-09 verdict kept the Areas rule a
recommendation rather than a check, and a declared warning under violation 10
is what that means here.

**One level, never two.** `CONTEXT.md` names `knowledge/INDEX.md`
directly instead of the four branch routers. The branch `CONTEXT.md` files stay
for human and Obsidian navigation — a model that has read the index has already
routed, and descending into a branch router is a second routing level.

### Why this shape

Replaces lore's blanket per-turn knowledge injection (72 entries in one
observed session), measured in `journal/2026/09/2026-09-10_lore-reevaluation.md`.

- **Anthropic, "Effective context engineering for AI agents"** — a finite
  attention budget; find the smallest high-signal set; prefer just-in-time
  retrieval over up-front loading.
- **Zhao, Wang & Chen 2026 (arXiv 2607.17598)** — one level of disclosure
  suffices; a second routing level "never helps and sometimes breaks accuracy
  outright". This is why the branch hop was removed rather than kept above the
  index.
- **Chroma, "Context Rot" (18 models, 194,480 calls)** — distractors, i.e.
  topically related content that does not answer the question, degrade accuracy
  more as input grows. Unrequested adjacent entries are exactly that condition.

### Known duplication

A leaf's `summary:` and its row in the branch router say the same thing in two
places. The branch routers are hand-written, not generated: `areas/CONTEXT.md`
indexes Areas rather than leaves, so generating one would destroy human
judgement to remove
a cosmetic repeat. The leaf is canonical; a router row that disagrees with its
leaf's `summary:` is the router's bug.
