# `memory/` as an Obsidian vault

`06_SYSTEM/memory/` is an Obsidian vault. Nothing was added to make this work
beyond `.obsidian/` config — the tree was already markdown with dense
cross-references, which is what a vault is.

## Why the vault root is `memory/`, not `knowledge/`

The interesting graph spans the stores. Skills cite knowledge leaves; journal
entries cite both. Rooting at `knowledge/` would cut every skill→knowledge edge
— precisely the edges worth seeing. Graph view over `memory/` shows which
knowledge is load-bearing and which leaves nothing points at; those orphans are
pruning candidates that no script surfaces as clearly.

## This is a second vault, not a replacement

`~/03_ZETTEL` remains the primary vault and the user's thinking space (domain
D1). This is D3 — operational knowledge about running the system. They are
deliberately separate: different content, different write authority, different
retention. Open both; do not merge them.

## Configuration

`useMarkdownLinks: true` and `newLinkFormat: relative` are **not optional**.
The tree uses relative markdown paths ([[memory-ranking]]) because
agents read these files as plain text through many harnesses, none of which
understand `[[wikilinks]]`. Obsidian must match the format the agents rely on,
not the other way round. `alwaysUpdateLinks: true` so renames repair references
rather than silently breaking citations.

Committed: `app.json`, `core-plugins.json`, `appearance.json`.
Git-ignored: `workspace.json`, `graph.json`, `plugins` — per-machine UI state.

## The one hazard

Obsidian edits are hand edits. Two rules still apply inside the vault:

1. **Never edit a `CONTEXT.md` categories block** — routers are generated by
   `familiar skills index` and hand edits are overwritten.
2. **Respect the caps.** `../../../../config/practice/user/user-identity.md` ≤ 1375 chars. Obsidian
   shows a word count, not a character count — check with `wc -c`. (`MEMORY.md`
   carried the other cap until it was deleted 2026-09-04.)

## What this supersedes

`OBSIDIAN-CLAUDE-SETUP.md` (1,116 lines) was an installation procedure for a
different stack — OpenClaw, Claude Vault, topic-note scanning, orphan linking of
exported conversations. Its goal was to get agent conversations into a navigable
vault. This architecture reaches that goal structurally instead: the journal is
already dated markdown, knowledge is already linked, and both are already in
git. The setup document is obsolete rather than merely unused.
